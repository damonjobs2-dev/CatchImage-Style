# 批量重新包装与设计

仅在用户要求把参考风格应用到其他图片时读取。当前 Agent 编排自己的视觉、生图和文件能力，不要求创建子 Agent，也不要求用户安装另一套 CatchArt Skill。

## 输入与分工

- **风格来源**：一张可清楚观察的参考图，或用户提供的现有 `style.md`。新图先按提取流程生成风格档案；现有档案直接使用，保留其中的不确定项。
- **主体来源**：每张待重新设计的图片。逐张核对人物、物件、造型、服装、姿态与关键配件，避免把风格参考图中的人物复制到全部结果。
- **目标**：用户指定的用途、画幅、版式、文案和保留项。能从上下文确定的直接执行；只有会改变主体或交付的问题才澄清。用户只要求提取风格时，到档案交付即完成。

## 设计与执行

1. 从档案选定 3–5 个整批共用的风格锚点，例如媒介表现、明暗层级、材质、颗粒、图文关系或光效。保持锚点一致；原图主体、画幅和每个像素的位置不必机械沿用。
2. 建立逐图对应关系，写清每张保留什么、改变什么。根据用户目标调整色系，保留主辅色、冷暖、明度与面积关系；颜色不应成为统一风格的唯一依据。摄影、插画与非人形主体分别处理，不默认所有输入都变成三维人物。
3. 为每张图编写独立生成指令，共用同一份风格描述。明确标注生图工具中每张参考图的角色：主体、风格、构图。需要保留的脸部特征、轮廓、服装和配件写为约束；额外道具或界面文案以用户要求为准。
4. 使用宿主当前可用的生图工具，并遵循该工具对参考图片、尺寸、调用和审核的要求。已有可用系列样本可作为辅助风格参考。用户已授权批量生成时，可完成整批，无需例行逐张询问；用户要求先看一张时按其要求停在样张。
5. 检查每张结果：主体是否对应、关键特征是否丢失、构图与用途是否匹配、风格锚点是否一致、有无意外文字或多余人物。实际打开结果后才标记完成；首次风格偏差可做有针对性的修正。

风格统一不等于身份和造型完全无损。用户指定必须保留的细节优先核对；无法可靠保留时如实说明，不声称精准复制。

## 工具缺失或失败

- 没有生图能力时，仍交付 `style.md`、逐图生成指令及待执行清单，明确本轮未生成图片。
- 调用失败时记录对应图片、状态与工具提供的安全错误信息，保留已完成结果。审核拒绝不被包装为“成功”，也不擅自切换服务规避限制；需要调整内容时与用户沟通。
- 切换付费服务、外部上传或新增密钥配置时，按宿主工具和用户授权边界执行，不把私有配置写入风格档案或发布包。

## 一个任务一个目录

采用主入口的 `<核心关键词>_style_<YYYYMMDDHHmmss>` 命名规则。批量任务在同一目录内组织：

```text
<核心关键词>_style_<时间>/
  reference.<扩展名>     风格参考图（可取得时）
  style.md               可独立阅读的风格档案
  inputs/                待重新设计的原始输入副本
  outputs/               每张独立生成图，采用与输入对应的名称
  prompts.md             最终使用的逐图指令
  manifest.md            输入、输出、结果状态与必要的差异说明
```

图片与文档采用相对链接；原输入保持不变，重试采用新文件名。用户明确要求延续已有系列时可沿用其任务目录，保留旧结果并避免覆盖。可选 ZIP 只打包实际产物，不把未完成项标为已交付。

## 最后给用户什么

简短说明共处理几张、完成几张、共同的风格及必要差异；展示实际结果，链接任务目录或打包文件。保留 `style.md` 和最终逐图指令，便于换 Agent 或换主题继续创作。失败或待执行项单独列清，图像模型能力和服务审核不能由 Skill 保证。
