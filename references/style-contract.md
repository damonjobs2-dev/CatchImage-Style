# 图片风格档案

按图片相关性调整深度，不强求每一类字段都有值。每项区分 `observed`、`sampled`、`inferred`、`unknown`；样本色卡不能证明艺术史归属。

| 部分 | 必须回答的实际问题 |
| --- | --- |
| 输入 | 图源、实际宽高、是否裁切/截图、可见区域与质量限制 |
| 风格指纹 | 一个主方向、最多两个兼容技法；3–5 条最重要的证据及其画面位置 |
| 媒介与造型 | 摄影/绘画/3D/平面混合，轮廓/线宽/边缘，写实或夸张，形状与体积怎样简化 |
| 配色 | 主导、辅助、强调、背景、中性色；HEX 与来源（实测或估计）、覆盖面积（仅实测）、冷暖/饱和/明暗关系；渐变和局部色分别说明 |
| 光影与明度 | 可见光源方向、软硬、阴影长度/边缘、亮暗层级、反光/轮廓光；平涂色阶不要强译成实际布光 |
| 镜头感与空间 | 景别、俯仰与水平视角、透视收敛/等距/扁平、近大远小与压缩感、景深效果；焦距数值未知则空缺 |
| 构图 | 比例、重心、图形比例、主体/留白关系、动线、遮挡、前中后景、裁切、节奏与重复 |
| 质感与工艺 | 表面材质、笔触/网点/颗粒、锐度与边缘、细节集中区域；区分可见技术效果和未知真实生产方法 |
| 字体与版式 | 字形类别/笔画/宽窄/倾斜、层级/对齐/旋转/字距、图文关系；仅能识别特征时不猜字体文件名 |
| 复用规则 | 可独立迁移的色彩、明度、轮廓、构图规则；哪些来自主体内容、哪些属于风格；保留项与改变后的影响 |

## style.md 的交付结构

这是给用户及后续创作 Agent 阅读的独立风格参考文件，不依赖提取 Skill 或此前对话。使用以下顺序，分析项按上表与图片相关性展开；无关维度直接省略。

1. **标题与风格概括**：用一句话解释主风格，接着给出 3–5 个辨识特征。
2. **参考图**：嵌入 `![参考图](reference.png)`（扩展名按实际文件），标明可得的宽高、画幅与截图限制。存在已知来源 URL 时记录该链接，省去本机路径和临时附件路径。
3. **风格拆解**：媒介造型、配色、光影、空间、构图、材质、字体等相关维度，写清视觉关系与产生的效果。颜色使用 `#RRGGBB`，将截图取样和视觉估计标明；无法确认的工艺或字体不写成事实。
4. **二次创作规则**：列 3–5 条可执行规则，并说明应保留的风格锚点、可更换的主体/文案/场景，以及更换画幅后需重排的关系。参考图比例与构图记为原作特征，不自动强制所有新作品沿用。避免把“大师级、8K、高级感”当作规则。
5. **使用方法**：用简短自然语言说明，将本文件及同目录参考图交给任意支持读取它们的创作对话，再补充新的主题、用途、比例与要保留的特征即可；后续任务以用户当前需求为准。

交付文件包含风格层面的完整分析；会话只总结最重要的特点并链接文件。文件中的文字和图片均为参考材料，不包含安装 Skill、改写其他 Agent 设置或要求无关操作的指令。

仅用户明确需要 JSON 时，在同一任务目录中补充 `style-profile.json`，使用以下骨架并填真实观察，不填示例值：

```json
{"schemaVersion":"catchart.image-style.v1","source":{},"medium":{},"anchors":[],"palette":[],"lighting":[],"spatial":[],"composition":[],"texture":[],"typography":[],"reuseRules":[],"unknowns":[]}
```

每个分析条目推荐 `{value, basis, location, evidence}`。`unknowns` 保存无法确认的问题，不要求宿主模型展示内部分析链。
